================================================================
SAMMANFATTNING
================================================================

Privatekonomi är ett ämne som berör alla men som många
upplever som svårt att hålla koll på. Målet med detta projekt
har varit att utveckla en fullständig, dynamisk webbapplikation
kallad SmartBudget, där användare kan registrera inkomster,
fasta kostnader och rörliga utgifter för att få en tydlig
bild av sin ekonomiska situation.

Applikationen har utvecklats med PHP och MySQL som kärn­
teknologier, med PDO och prepared statements för säker
databashantering. Autentiseringssystemet använder PHP-sessioner
och bcrypt-lösenordshashning via password_hash(). JavaScript
används för klientsidig interaktivitet, bland annat AJAX-baserad
borttagning av poster utan sidomladdning, och CSS3-animationer
skapar ett modernt och professionellt gränssnitt.

Projektet integrerar två externa API:er: World Bank Open Data
API hämtas direkt i webbläsaren för att visa Sveriges
genomsnittliga inkomst, medan Riksbankens Open API anropas
server-side via PHP/cURL för att kringgå CORS-begränsningar.
Statistiksidan visualiserar all data med interaktiva diagram
via Chart.js-biblioteket.

En administratörspanel möjliggör användarhantering med
IP-spårning, suspend-funktion och radering av konton.

Det största tekniska problemet under projektet var CORS-felet
med Riksbankens API, som löstes genom att flytta anropet
till PHP-servern. Projektet uppfyller kursens samtliga krav
och demonstrerar kunskaper inom databaser, serverlogik,
API-integration, säkerhet och modern webbutveckling.

Nyckelord: PHP, MySQL, PDO, API, AJAX, CSS-animationer,
           privatekonomi, webbapplikation, autentisering

1.1  Bakgrund och problemmotivering
------------------------------------
Personlig ekonomi är ett ämne av fundamental betydelse för
alla individer, men undersökningar visar att många saknar
konkreta verktyg för att hålla koll på sin budget [1]. En
studie från Finansinspektionen (2023) visar att var tredje
svenska hushåll upplever att de har svårt att få ekonomin
att gå ihop [2]. Digitala hjälpmedel för privatekonomisk
planering finns på marknaden, men befintliga lösningar är
ofta komplexa, kräver betalprenumerationer eller är inte
anpassade för svenska ekonomiska förhållanden.

Webbapplikationer erbjuder en naturlig plattform för
privatekonomiska verktyg, eftersom de är plattformsoberoende
och kräver ingen installation. PHP och MySQL är sedan länge
etablerade teknologier för serversidiga webbapplikationer [3]
och utgör en lämplig bas för detta projekt.

SmartBudget är en webbbaserad applikation skapad för att
ge användare enkel och överskådlig kontroll över sin
månadsbudget. Applikationen är byggd med öppen källkod­
mjukvara och körs lokalt via XAMPP-miljön.

1.2  Övergripande syfte
------------------------
Projektets övergripande syfte är att omsätta kursens moment
i ett sammanhängande, fullständigt projekt. Syftet är att
skapa en dynamisk webbapplikation som demonstrerar kunskaper
inom databas­hantering, sessionsbaserad autentisering,
API-integration och klientsidig interaktivitet.

Projektet syftar också till att undersöka hur externa API:er
från svenska myndigheter (Riksbanken) kan integreras i en
webbapplikation, och hur CORS-begränsningar kan hanteras.

1.3  Avgränsningar
-------------------
Undersökningen och implementationen är avgränsad till
följande:

  - Applikationen körs lokalt via XAMPP och är inte
    driftsatt på en publik server.
  - Inga riktiga pengatransaktioner eller bank­kopplingar
    hanteras — all data är användarskapad.
  - Mobilanpassning är implementerad men inte djuptestad
    på fysiska mobila enheter.
  - Applikationen stöder enbart det svenska språket.
  - Projektet genomförs som enskilt arbete.

1.4  Konkreta och verifierbara mål
------------------------------------
Undersökningen har som mål att besvara följande frågor:

  M1: Kan en komplett autentiseringsmodul (registrering,
      inloggning, sessionshantering) implementeras säkert
      med PHP och MySQL?

  M2: Kan AJAX och JavaScript användas för att förbättra
      användarupplevelsen vid borttagning av poster,
      så att sidomladdning undviks?

  M3: Kan data från externa API:er (World Bank, Riksbanken)
      integreras och visualiseras med Chart.js?

  M4: Kan CORS-begränsningar för Riksbankens API hanteras
      server-side med PHP/cURL?

  M5: Kan ett funktionellt administratörs­gränssnitt
      med IP-spårning och suspend-funktion implementeras?

2.1  Dynamiska webbapplikationer med PHP
-----------------------------------------
En dynamisk webbapplikation genererar HTML-innehåll
server-side baserat på data, sessioner och användar­input,
i motsats till statiska webbsidor [3]. PHP (Hypertext
Preprocessor) är ett serversidig skriptspråk som körs
på webbservern och skickar färdig HTML till klienten.

PHP hanterar HTTP-förfrågningar, interagerar med databaser
och hanterar sessioner via $_SESSION-superglobal [4].
PHP 8+ introducerade förbättrade typannotationer och
match-uttryck, vilket förbättrar kodens läsbarhet.

Apache HTTP Server fungerar som webbserver och vidare­
befordrar förfrågningar till PHP-interpretern. XAMPP
(Apache + MariaDB + PHP + Perl) är ett lokalt
driftsättningspaket som förenklar utvecklingen [5].

2.2  Databashantering med MySQL och PDO
-----------------------------------------
MySQL är ett relationsdatabas­system som lagrar data i
tabeller med definierade relationer [6]. SQL (Structured
Query Language) används för att skapa, läsa, uppdatera
och radera data (CRUD-operationer).

PDO (PHP Data Objects) är PHP:s abstraktionslager för
databasåtkomst [4]. Prepared statements (förberedda
satser) separerar SQL-kod från data, vilket eliminerar
risken för SQL-injektion [7]. En prepared statement
kompileras en gång och kan köras upprepade gånger med
olika parametrar:

  $stmt = $pdo->prepare("SELECT * FROM users WHERE id=?");
  $stmt->execute([$id]);

Foreign keys med ON DELETE CASCADE säkerställer referentiell
integritet — när en användare raderas raderas automatiskt
all kopplad data [6].

2.3  API:er och CORS
----------------------
Ett API (Application Programming Interface) är ett
gränssnitt som möjliggör kommunikation mellan system [8].
REST-API:er returnerar vanligen data i JSON-format via
HTTP-protokollet.

CORS (Cross-Origin Resource Sharing) är en webbläsar­
säkerhetspolicy som blockerar JavaScript-anrop till
en annan domän än den aktuella sidan [9]. Om en webbsida
på localhost försöker hämta data från api.riksbank.se,
blockerar webbläsaren anropet om api.riksbank.se inte
inkluderar rätt CORS-headers i svaret.

Lösningen är att flytta API-anropet till servern.
PHP:s cURL-bibliotek kan göra HTTP-förfrågningar utan
CORS-begränsningar, eftersom begränsningen enbart
gäller webbläsarbaserad JavaScript [4].

2.4  Säkerhet i webbapplikationer
-----------------------------------
OWASP (Open Web Application Security Project) definierar
de vanligaste webbsårbarheterna i OWASP Top Ten [7].
För detta projekt är följande relevanta:

SQL-injektion: Angripare kan manipulera SQL-frågor
genom att injicera kod i formulärinput. Prepared
statements förhindrar detta genom att parametrar
aldrig tolkas som SQL-kod [7].

XSS (Cross-Site Scripting): Skadlig JavaScript kan
injiceras i en webbsida om användardata visas utan
att specialtecken kodas. PHP:s htmlspecialchars()
omvandlar < > " & till HTML-entiteter [4].

Lösenordssäkerhet: Lösenord ska aldrig lagras i
klartext. PHP:s password_hash() med bcrypt­algoritmen
skapar ett salt och hashar lösenordet. password_verify()
jämför klartextlösenord mot det lagrade hashvärdet [4].

3  METOD
================================================================

Projektet genomfördes med en iterativ arbetsmetod uppdelad
i fyra faser, där varje fas byggde på föregående.

Fas 1 — Infrastruktur och planering (vecka 1–2):
  Storyboard och flödesschema ritades upp. Databas­schemat
  designades och tabellerna skapades via phpMyAdmin.
  Grundfilerna för inloggning, registrering och sessions­
  hantering implementerades.

Fas 2 — Kärnfunktioner (vecka 3–4):
  Dashboard med CRUD-operationer implementerades.
  AJAX-borttagning testades och verifierades manuellt.
  Varje funktion testades isolerat innan integration.

Fas 3 — API och statistik (vecka 5–6):
  World Bank API testades i webbläsarens konsol.
  Riksbankens API testades med cURL i terminalen.
  CORS-problemet identifierades och löstes (se 6.2).
  Statistiksidan med Chart.js implementerades och validerades
  mot riktig API-data.

Fas 4 — Design, admin och optimering (vecka 7–8):
  Designsystemet implementerades med CSS-variabler och
  keyframes-animationer. Administratörspanelen byggdes.
  Koden rensades från dubbletter och oanvända filer.

Testmetod:
  Funktionella tester genomfördes manuellt för varje
  funktion (se kapitel 5). Säkerhetstester utfördes
  med kända attack­vektorer (SQL-injektion, XSS).
  Kompatibilitet testades i Chrome, Firefox och Edge.

Valda programvaror redovisas i avsnitt 4.9.

4.3  Databasdesign
-------------------
Databasen "smartbudget" består av fyra tabeller.
Alla tabeller använder InnoDB-lagringsmotorn för att stödja
foreign key-relationer [6].

TABELL: users
  Kolumn       Typ            Beskrivning
  id           INT PK AI      Primärnyckel, auto increment
  username     VARCHAR(100)   Unik, används vid inloggning
  name         VARCHAR(100)   Visningsnamn (display name)
  email        VARCHAR(255)   E-postadress (valfritt)
  password     VARCHAR(255)   Bcrypt-hashad med password_hash()
  role         VARCHAR(20)    Värde: 'user' eller 'admin'
  created_at   DATETIME       Tidpunkt för registrering
  last_login   DATETIME       Tidpunkt för senaste inloggning
  last_ip      VARCHAR(45)    IP-adress vid senaste inloggning
  suspended    TINYINT(1)     0 = aktiv, 1 = suspenderad

TABELL: incomes
  Kolumn       Typ            Beskrivning
  id           INT PK AI      Primärnyckel
  user_id      INT FK         Foreign key → users.id
  name         VARCHAR(255)   Beskrivning av inkomstkällan
  amount       DECIMAL(10,2)  Belopp i kronor
  created_at   DATETIME       Tidpunkt

TABELL: fixed_expenses   (identisk struktur som incomes)
TABELL: variable_expenses (identisk struktur som incomes)

Relationer:
  users (1) ──────< incomes (många)
  users (1) ──────< fixed_expenses (många)
  users (1) ──────< variable_expenses (många)

Alla foreign keys definieras med ON DELETE CASCADE [6],
vilket automatiskt raderar en användares data när
användarkontot raderas.

Figur 1: ER-diagram (beskrivet textuellt)
  [users] 1──< [incomes]
  [users] 1──< [fixed_expenses]
  [users] 1──< [variable_expenses]


4.4  Sidornas konstruktion
---------------------------
Alla skyddade sidor börjar med:
  require 'includes/auth.php';
  require 'config/db.php';

auth.php startar sessionen och kontrollerar att
$_SESSION['user_id'] är satt. Om inte sker omdirigering
till login.php.

config/db.php skapar en PDO-instans med en try-catch-
konstruktion som hanterar anslutningsfel.

HEADER OCH FOOTER:
includes/header.php öppnar HTML-dokumentet, laddar
Google Fonts och CSS, och renderar sidebaren. Sidebaren
visar Admin-länken villkorligt:
  <?php if($_SESSION["role"] === "admin"): ?>
  <a href="admin_dashboard.php">Admin</a>
  <?php endif; ?>

includes/footer.php stänger HTML-taggar och laddar
JavaScript-filen luxury.js.

DASHBOARD:
PHP hämtar data med tre separata prepared statements,
en per tabell. Summorna beräknas i PHP:
  $totalIncome = array_sum(array_column($incomes, "amount"));
  $remaining   = $totalIncome - $totalExpenses;
  $savingPct   = $totalIncome > 0
                   ? round(($remaining / $totalIncome) * 100) : 0;

PHP-variablerna bäddas in i ett JavaScript-block för
live-uppdatering:
  let totals = { income: <?= $totalIncome ?>,
                 expenses: <?= $totalExpenses ?> };

Varje budgetrad har data-attribut som JavaScript läser:
  <div class="budget-row"
       data-amount="<?= $item['amount'] ?>"
       data-type="income">

STATISTIK:
PHP kör cURL mot Riksbankens API (se 4.7) och bygger
PHP-arrayer ($cpifLabels, $cpifValues). Dessa skickas
direkt till Chart.js via json_encode():
  labels: <?= json_encode($cpifLabels) ?>

World Bank API hämtas asynkront i JavaScript med fetch().


4.5  Interaktion med JavaScript och AJAX
-----------------------------------------
JavaScript-filen luxury.js innehåller fem funktioner:

initParticles(canvasId):
  Skapar ett canvas-baserat partikelssystem med 90 guld­
  färgade partiklar som rör sig slumpmässigt. Partiklar
  kopplas med linjer om de är inom 130 pixlar från
  varandra. Ytterligare linjer dras mot musens position.
  requestAnimationFrame() används för effektiv animering [10].

init3DTilt(selector, intensity):
  Lyssnar på mousemove-händelser och beräknar elementets
  lutning relativt musens position. CSS perspective och
  rotateX/rotateY appliceras för ett 3D-korteffekt.

animateCount(el):
  Animerar tal från 0 till slutvärdet med ease-out cubic
  easing över 1 400 millisekunder. PHP:s number_format()
  returnerar "5 000,00" varför regex-replace krävs innan
  parseFloat():
    .replace(/,(?=\d{3})/g, '')

initScrollReveal():
  IntersectionObserver triggar fadeUp-CSS-animationen när
  element scrollar in i vyn [10].

initMagneticButtons():
  Knappar förflyttas svagt mot muspositionen (25% av
  avvikelsen från knappens center) för en magnetisk effekt.

AJAX-borttagning i dashboard.php:
  Vid klick på ta bort-knappen:
  1. CSS-övergången startas (opacity 0, translateX, maxHeight)
  2. fetch() skickas till delete_item.php med header
     'X-Requested-With: XMLHttpRequest'
  3. delete_item.php returnerar JSON: {"ok": true}
  4. Live-summorna uppdateras i JavaScript
  5. updateSummary() räknar om återstående belopp och spargrad
  6. Raden tas bort från DOM efter 700ms fördröjning

4.7  Externa API-integrationer
--------------------------------
WORLD BANK OPEN DATA API [11]:
  Endpoint: api.worldbank.org/v2/country/SE/indicator/
            NY.GNP.PCAP.PP.CD?format=json&per_page=5

  Anrop sker med JavaScript fetch() direkt i webbläsaren.
  API:et tillåter cross-origin-förfrågningar (CORS ok).
  Responsen är en JSON-array där index 1 innehåller
  datapunkterna. Koden filtrerar på value !== null och
  tar det senaste årtalet:
    const e = d[1]?.find(x => x.value !== null);
    const monthly = Math.round(e.value / 12);

  Resultatet jämförs med användarens registrerade inkomst
  och presenteras i ett stapeldiagram med Chart.js.

RIKSBANKENS OPEN API [12]:
  Endpoint: api.riksbank.se/swea/v1/Observations/
            {seriesId}/{from}/{to}

  Dataserier:
    SECPIFASTPCT12  CPIF-inflation, 12 månaders förändring
    SETBREPOEFF     Effektiv styrränta

  API:et blockerar webbläsaranrop med CORS-policy.
  Lösningen är att anropa API:et server-side via PHP/cURL:

    function riksbankGet(string $seriesId, ...): ?array {
        $ch = curl_init($url);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT        => 6,
            CURLOPT_HTTPHEADER     => ['Accept: application/json'],
        ]);
        $body = curl_exec($ch);
        ...
    }

  Svaret parsas med json_decode() och filtreras för att
  ta bort null-värden. Resultaten byggs till PHP-arrayer
  som skickas till Chart.js via json_encode().

  Baserat på aktuell inflation och styrränta genereras
  ett kontextuellt råd: exempelvis "Inflationen är hög
  (X%). Sparpengar tappar värdet — kolla högräntekonton."

CHART.JS [13]:
  JavaScript-bibliotek för att rendera interaktiva diagram.
  Laddas via CDN (Content Delivery Network) från jsdelivr.net.
  Tre diagramtyper används: bar (stapel), line (linje)
  och doughnut (cirkel).


4.8  Administratörspanel
-------------------------
Administratörspanelen är tillgänglig enbart för användare
med rollen 'admin'. Behörighets­kontrollen sker i PHP:
  if($_SESSION["role"] !== "admin") {
      header("Location: dashboard.php");
      exit;
  }

Panelen hämtar alla användare med en komplex SQL-query
som inkluderar subqueries för att räkna antal poster:
  SELECT u.*,
    (SELECT COUNT(*) FROM incomes WHERE user_id=u.id) +
    (SELECT COUNT(*) FROM fixed_expenses WHERE user_id=u.id) +
    (SELECT COUNT(*) FROM variable_expenses WHERE user_id=u.id)
    AS activity_count
  FROM users u ORDER BY created_at DESC

För varje användare visas: namn, användarnamn, roll,
senaste IP-adress, antal poster, senaste inloggningstid
och aktiv/suspenderad status.

IP-adressen sparas vid varje lyckad inloggning i login.php:
  $ip = $_SERVER['HTTP_X_FORWARDED_FOR'] ?? $_SERVER['REMOTE_ADDR'];
  UPDATE users SET last_login = NOW(), last_ip = ? WHERE id=?

Alla adminåtgärder (suspend/unsuspend/delete) skickas som
POST-förfrågningar till admin_action.php via fetch().
Svaret är JSON och UI uppdateras utan sidomladdning.
En modal-dialog (bekräftelsepopup) visas innan radering.
Administratören kan inte agera på sitt eget konto —
detta skyddas i admin_action.php:
  if($id === intval($_SESSION['user_id'])) {
      echo json_encode(['ok' => false]); exit;
  }

6.1  Analys av resultaten
--------------------------
Samtliga konkreta mål (M1–M5) som formulerades i avsnitt 1.4
har uppnåtts:

M1 – Autentisering: En komplett autentiseringsmodul
implementerades med PHP-sessioner, bcrypt-hashning och
behörighetskontroll. Suspenderings­funktionen lades till
som utökning av grundkravet.

M2 – AJAX utan sidomladdning: Borttagning av poster
fungerar smidigt med animering och live-uppdatering
av summor. Användar­upplevelsen förbättrades markant
jämfört med traditionell form-submit med sidomladdning.

M3 – API-visualisering: Båda API:erna integrerades och
data visualiseras korrekt i Chart.js. World Bank-jämförelsen
och Riksbanken­datan ger genuint värde för användaren.

M4 – CORS-hantering: Riksbankens CORS-problem löstes
elegant via PHP/cURL. Lösningen är robust och hanterar
timeout och null-värden korrekt.

M5 – Administratörspanel: En komplett panel med
IP-spårning, suspend och radering implementerades
med AJAX och bekräftelsedialog.

6.2  Problem och lösningar
----------------------------
CORS-felet med Riksbankens API:
  Det första försöket hämtade data direkt i JavaScript
  med fetch(). Webbläsarens konsol visade:
  "Access to fetch at 'api.riksbank.se' from origin
  'localhost' has been blocked by CORS policy".

  Analys: Riksbankens API skickar inte Access-Control-
  Allow-Origin-headern i svaret, vilket krävs för att
  webbläsaren ska tillåta anropet [9].

  Lösning: Anropet flyttades till PHP-servern via cURL.
  PHP-servern har inga CORS-begränsningar eftersom
  restriktionen enbart gäller webbläsarbaserade anrop.
  Detta är den korrekta och rekommenderade lösningen
  för API:er som inte stödjer CORS [9].

Talformattering i JavaScript:
  PHP:s number_format() producerar "5 000,00" för
  talet 5000. JavaScript:s parseFloat("5 000,00")
  returnerade 5.0 eftersom parsern stannade vid mellanslaget.

  Lösning: Mellanslag och tusentals­komman tas bort
  med regex innan parseFloat() anropas:
    .replace(/\s/g, '').replace(/,(?=\d{3})/g, '')

CSS-webbläsarcache:
  Uppdaterad CSS visades inte i webbläsaren.
  Lösning: Cache-busting med query string på CSS-länken:
  style.css?v=4 tvingar webbläsaren att ladda ny version.

Klassnamnsfel i CSS:
  CSS definierade .auth-ring-1 men HTML använde
  .auth-brand-ring — en diskrepans som förhindrade
  rotationsanimationen. Löstes genom att synkronisera
  klassnamnen.

6.3  Vad fungerar bra och dåligt
----------------------------------
Fungerar bra:
  - AJAX-borttagning med smooth animation är smidig
    och ger en professionell känsla.
  - Partikelssystemet på startsidan presterar bra
    tack vare requestAnimationFrame.
  - 3D-kortlutningen fungerar utan externa bibliotek.
  - API-integrationerna ger genuint aktuell data.
  - Säkerhets­åtgärderna fungerar korrekt mot alla
    testade angreppsvektorer.

Fungerar mindre bra:
  - Mobilanpassningen är grundläggande — sidebar döljs
    men ingen hamburgermeny visas i mobilläge.
  - Riksbankens API har 6 sekunders timeout vilket
    kan göra statistiksidan långsam vid dålig anslutning.
  - Ingen möjlighet att återställa glömt lösenord.
